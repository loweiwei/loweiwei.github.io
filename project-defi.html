MiniBank｜DeFi Lending Protocol

區塊鏈期末專題｜DeFi MiniBank DApp

以 Solidity 與 Hardhat 實作一套可在本機鏈上完整操作的去中心化銀行 DApp。系統涵蓋 LP 供應 MiniDAI、借款人抵押 ETH 借出 MiniDAI、利息與協議收益分配、健康因子清算、BKT 獎勵，以及 Governor + Timelock 的 DAO 治理流程。

MiniBank System Pipeline

Project Motivation

專題動機與目標

在區塊鏈課程中學習 DeFi 借貸與治理機制後，我希望不只停留在概念理解，而是實作一個能實際部署、透過 MetaMask 操作、並以測試覆蓋主要情境的鏈上系統。MiniBank 將借貸協議拆成資產、份額、Oracle、核心 Bank、治理代幣、Governor 與 Timelock 等模組，讓每個角色的資金流與權限邊界都能被清楚驗證。

使用技術與開發環境

MiniBank System Overview

DeFi System Flow / Architecture

LP

Liquidity Provider

Supply mDAI → 提供流動性 → 取得 aMDAI Share → 獲得 BKT Reward

Borrower

Collateral Borrowing

Deposit ETH → 根據 LTV 借出 mDAI → Repay Principal + Interest

BankV3

Liquidity Pool Collateral / Debt / Interest / Reward / Liquidation
Liquidator

Risky Debt Handler

Health Factor < 0.9 時 Repay Risky Debt，取得 ETH Collateral + Liquidation Bonus。

Price Oracle

ETH/USD Price

計算 Collateral Value、Borrow Limit、Health Factor 與 Liquidation Condition。

DAO / BKT Holder

Governance

Delegate → Propose → Vote → Timelock → 更新協議參數。

Smart Contract Modules

合約模組設計

系統核心是 BankV3，其餘合約分別負責穩定幣、LP share、價格來源、治理票權與延遲執行，避免把所有權限集中在單一使用者。

BankV3.sol

借貸核心合約，管理 ETH collateral、MiniDAI debt、LP pool、interest、liquidation、reward accounting 與 DAO 可調參數。

MiniDAI.sol

協議內 ERC20 穩定幣，作為 LP supply、borrow、repay 與 liquidation 使用的資產。

aMDAI.sol

LP share token。LP supply 後鑄造 aMDAI，redeem 時燒毀並依 pool share 取回 MiniDAI。

PriceOracle.sol

測試用 ETH/USD Oracle，可在 demo 中模擬 ETH 價格下跌，觸發健康因子變化與清算。

BankToken.sol

BKT，使用 ERC20Votes，兼具 reward token 與 DAO governance voting power。

BankGovernor / BankTimelock

以 OpenZeppelin Governor + TimelockController 實作提案、投票、queue、delay 與 execute。

Execution Pipeline

部署與前端互動流程

Deploy Pipeline

  1. 啟動 Hardhat local node。
  2. 部署 PriceOracle、MiniDAI、BankToken、aMDAI 與 BankV3。
  3. 設定 MiniDAI minter 與 aMDAI bank 權限。
  4. 部署 BankTimelock 與 BankGovernor。
  5. 將 BankV3 governance 移交給 Timelock。
  6. 輸出 ABI 與 contract-address.json 給前端使用。

DApp Interaction Pipeline

  1. 開啟 frontend/index.html。
  2. 連接 MetaMask 與 local Hardhat network。
  3. 前端讀取 ABI 與部署地址。
  4. 透過 ethers.js 建立 Contract instance。
  5. 使用 signer 發送 supply、borrow、repay、liquidate、claimReward 與 DAO transaction。

Key Concepts

LTV / Health Factor

LTV

Loan-to-Value

決定抵押品最多能借出多少資產。

Borrow Limit = Collateral Value × LTV
ETH CollateralBorrow LimitBorrow mDAI

Health Factor

清算風險指標

衡量目前抵押品是否足以支撐債務。

HF ≥ 0.9 → Safe
HF < 0.9 → Liquidatable
Parameter設定 / 作用設計目的
LTV預設 80%限制借款人最多可依抵押品價值借出的 MiniDAI 數量。
Health FactorCollateral Value / Debt衡量帳戶是否接近清算風險。
Liquidation Threshold預設 0.9讓系統在抵押不足時能由第三方處理高風險債務。
Reserve Factor預設 10%將部分利息或清算收入保留為 protocol reserve。
Daily CapBKT 每日發放上限避免 reward 無限制增發，控制 LP 與 borrower 激勵。

Lending Flow

借貸流程

LP Supply mDAI Liquidity Pool Borrower Deposit ETH Borrow mDAI Repay + Interest LP 收益 / Protocol Reserve
Health Factor < 0.9 Liquidator Repay Debt Receive ETH Collateral + Bonus

LP Supply / Redeem

LP approve MiniDAI 後呼叫 supply(amount)，BankV3 將資金加入 liquidityPool 並 mint aMDAI。贖回時依 aMDAI share 計算可取回的 MiniDAI。

Borrow / Repay

借款人抵押 ETH 後，BankV3 透過 Oracle 計算 collateral value 與 max borrow。還款時會拆分本金、LP 收益與 protocol reserve。

Liquidation

當 ETH 價格下跌或債務增加導致 Health Factor 低於門檻，清算人可代償部分 MiniDAI，取得 ETH collateral 與 liquidation bonus。

Incentive & Revenue Distribution

參與誘因與收益分配

LP

提供流動性，取得 aMDAI Share、部分借款利息與 BKT Reward。

Borrower

保留 ETH Exposure，同時取得可使用的 mDAI 流動性。

Liquidator

協助處理高風險債務，取得 Collateral 與 Liquidation Bonus。

Protocol / DAO

從利息與清算機制中累積 Protocol Reserve，並透過 BKT Governance 管理協議參數。

LP 提供的不是單純「存款」，而是可供 Borrower 使用的流動性；作為交換，LP 取得資金池份額並分享協議收益。

DAO Governance

DAO Governance

BKT Holder Delegate Voting Power Proposal Voting Timelock Execute
Interest Rate Reserve Factor Reward Parameters Proposal Threshold Quorum Inject Reserve to LP

部署完成後，BankV3 的治理權限會轉移到 Timelock，因此調整利率、每日 BKT 發放上限、reserve factor、LP / borrower reward ratio、proposal threshold 與 quorum 等參數，都必須經過 DAO 提案、投票、排程與延遲執行。
