Project Story

專題定位：把 DeFi Lending 從概念做成可操作協議

MiniBank 的目標不是只展示一個單一智能合約函式，而是把「去中心化借貸」拆成可部署、可互動、可測試的完整協議。讀者可以把它想成一個小型 Aave / Compound prototype：有人提供穩定幣流動性，有人抵押 ETH 借出穩定幣，系統用價格與健康因子控制風險，最後再用 DAO 取代單一管理者調整參數。

因此，這個頁面會依照實際系統的閱讀順序說明：先看整體目標與技術棧，再看架構中每個角色與資產，接著看合約如何分工，最後沿著一筆資金的生命週期理解供應、借款、還款、清算、獎勵與治理。

我實作的是什麼

一套本機鏈上可部署的去中心化銀行 DApp，包含 Solidity 合約、Hardhat 部署腳本、MetaMask 前端互動、DAO 治理流程與測試案例。

核心問題是什麼

如何讓 LP 的資金能安全借出、讓 Borrower 依抵押品取得流動性、讓風險帳戶可被清算，並讓協議參數由治理流程調整。

閱讀這頁的方法

先理解 BankV3 是核心帳本，再看 MiniDAI、aMDAI、BKT、Oracle 與 Governor 如何圍繞 BankV3 組成完整協議。

Tech Stack & Deployment

先建立一個能被部署與操作的鏈上環境

這個專題的第一層是工程環境：Hardhat 負責合約編譯、本機節點、部署與測試；Solidity 合約負責鏈上狀態；前端使用純 HTML / JavaScript 與 ethers.js v6 連接 MetaMask。部署腳本會把合約地址與 ABI 輸出到 frontend/，讓前端可以直接讀取並呼叫鏈上合約。

Deploy Pipeline

部署流程先建立資產與核心協議，再把權限交給治理系統，最後輸出前端需要的 ABI 與地址。

  1. 啟動 Hardhat local node。
  2. 部署 PriceOracle、MiniDAI、BankToken、aMDAI 與 BankV3。

System Architecture

整個系統圍繞 BankV3：資產、角色、風險與治理都回到同一個核心帳本

MiniBank 的架構可以從中心往外看：BankV3 是借貸帳本與狀態管理核心；MiniDAI 是流動性與借款資產；aMDAI 代表 LP 的 pool share；PriceOracle 讓系統能把 ETH 抵押品換算成美元價值；BankToken 提供 reward 與 voting power；BankGovernor 和 BankTimelock 則負責治理提案與延遲執行。

LP

Liquidity Provider

提供 MiniDAI 進入 liquidityPool，取得 aMDAI 作為池中份額，並累積 BKT reward。

Borrower

Collateral Borrowing

抵押 ETH，根據 Oracle 價格與 LTV 借出 MiniDAI，並在還款時支付利息。

BankV3

Protocol Ledger Collateral / Debt / Interest / Reward / Liquidation / Governance Parameters
Liquidator

Risk Handler

當 Health Factor < 0.9 時代償部分債務，取得 ETH collateral 與 liquidation bonus。

Price Oracle

ETH/USD Price

提供抵押品估值，影響可借額度、健康因子、提款限制與清算條件。

DAO

Governance Executor

BKT holder 透過 Governor 提案與投票，成功後由 Timelock 執行參數調整。

系統資產：每個 token 都有明確責任

為了讓借貸流程清楚，專題把資產分成抵押品、借貸資產、LP 份額與治理 / 獎勵代幣四類。

ETH

Collateral

Borrower 抵押 ETH，系統根據 ETH/USD 價格計算 collateral value 與可借額度。

mDAI

Liquidity / Debt Asset

MiniDAI 是 LP 供應、Borrower 借款、還款與 Liquidator 代償時使用的主要資產。

aMDAI

LP Share Token

LP supply 後獲得 aMDAI；redeem 時依 aMDAI 份額換回 pool 中可贖回的 MiniDAI。

BKT

Reward / Governance

BKT 同時作為 LP / borrower reward 與 DAO voting power，支援 delegate 與 proposal voting。

Smart Contract Design

合約分工：BankV3 管帳，其他合約各自處理資產、價格與治理

這個專題的合約不是平行堆疊，而是有明確依賴方向。BankV3 負責最重要的資金與帳務狀態；MiniDAI、aMDAI、BankToken 讓資產權責分離；PriceOracle 讓風險計算可以被測試；Governor 與 Timelock 則讓協議參數調整從 owner 操作轉成治理流程。

BankV3.sol

核心借貸合約，管理 liquidityPool、collateral、debt、interest、repayment split、liquidation、reward accounting 與 governance parameters。

MiniDAI.sol

協議內穩定幣。BankV3 被設定為 minter 後，能在借款流程中配合協議鑄造或移轉 MiniDAI。

aMDAI.sol

LP share token。只有 BankV3 能在 supply 時 mint、redeem 時 burn，用來追蹤 LP 在池中的份額。

PriceOracle.sol

測試用 Oracle，支援手動設定 ETH price，讓 demo 與測試能模擬價格下跌後的清算情境。

BankToken.sol

BKT 使用 ERC20Votes，部署時固定供應量，部分分配給 BankV3 作為 reward，並提供 DAO 投票權。

BankGovernor / BankTimelock

Governor 負責建立提案與投票；Timelock 負責延遲執行，並成為 BankV3 的 governance executor。

BankV3 Deep Dive

BankV3 是協議的狀態機

BankV3 同時追蹤 pool liquidity、使用者 collateral、使用者 debt、protocol reserve 與 reward。每次使用者 supply、borrow、repay、withdraw 或 liquidate，合約都必須更新多個狀態，並確保資金面與帳本面一致。

主要狀態

liquidityPool、totalDebtCached、totalCollateral、protocolTokenReserve、collateral[user]、debts[user]

核心函式

supply、redeem、depositCollateral、borrow、repay、liquidate、claimReward

DAO 可調參數

interestRate、dailyCap、reserveFactor、lpRewardRatio、borrowerRewardRatio、changeStatus

Protocol Flow

從一筆資金的生命週期理解借貸、還款、清算與獎勵

MiniBank 的主要流程可以用一條資金路徑串起來：LP 先把 MiniDAI 放進池中，Borrower 抵押 ETH 後從池中借出 MiniDAI，債務會隨時間累積利息；還款時利息會在 LP pool 與 protocol reserve 之間拆分；如果 ETH 價格下降或債務增加導致健康因子低於門檻，Liquidator 可以代償債務並取得抵押品獎勵。

LP Supply mDAI BankV3 Mint aMDAI Borrower Deposit ETH Borrow Under LTV Repay Principal + Interest LP Yield / Protocol Reserve
01

LP Supply / Redeem

LP approve MiniDAI 後呼叫 supply(amount)。BankV3 收到 MiniDAI，增加 liquidityPool，並 mint 等量 aMDAI 給 LP。當 LP 呼叫 redeem(amount)，系統會依 aMDAI / totalSupply 的比例計算可取回的 MiniDAI。

02

Borrow / Repay

Borrower 呼叫 depositCollateral() 抵押 ETH，BankV3 透過 PriceOracle 取得 ETH 價格，再依 80% LTV 計算可借額度。還款時 repay(amount) 會拆成本金減少、LP 收益與 protocol reserve。

03

Liquidation

當價格下跌或利息累積導致健康因子低於 0.9，清算人可呼叫 liquidate(user, repayAmount)。BankV3 會降低 borrower debt，將部分 ETH collateral 轉給 liquidator，並保留 reserve factor 收益。

04

Reward Claim

LP 與 borrower 都會依資產價值、時間與 reward ratio 累積 BKT。每日發放量受 dailyCap 限制，使用者可透過 claimReward(true/false) 領取 LP 或 borrower reward。

Borrow Limit

LTV 控制最大借款額度

LTV 讓 Borrower 不能借超過抵押品價值。此專題預設 LTV 為 80%，也就是抵押品價值越高，可借出的 MiniDAI 越多。

Borrow Limit = Collateral Value × 80%

Risk Signal

Health Factor 控制清算風險

Health Factor 會隨 ETH 價格與債務變化而改變。低於清算門檻時，系統允許第三方清算，避免壞帳長期留在池中。

HF ≥ 0.9 → Safe
HF < 0.9 → Liquidatable

DAO Governance

治理流程：把協議參數調整交給 BKT 持有人與 Timelock

在部署完成後，BankV3 的 governance 會轉移給 Timelock，而不是由部署者直接控制。這代表利率、reward ratio、daily cap、reserve factor、proposal threshold 與 quorum 等參數，都需要經過 BKT 持有人 delegate、建立提案、投票、queue 到 Timelock，最後再 execute。

BKT Holder Delegate Voting Power Create Proposal Vote Queue Timelock Execute
Interest Rate Reserve Factor Daily Cap LP Reward Ratio Borrower Reward Ratio Proposal Threshold Quorum Inject Reserve to LP

為什麼需要 Governor

Governor 負責提案生命週期，包含 voting delay、voting period、proposal state、票數查詢與 For / Against / Abstain 投票。這讓參數調整不再是單一 owner 的即時操作。

為什麼需要 Timelock

Timelock 是真正的執行者。即使提案通過，也必須 queue 並等待 minDelay 後才能 execute，讓治理結果有延遲與可觀察性。

Verification

測試重點：驗證資金帳本、清算邊界與 reward accounting

DeFi 專題最容易出錯的地方通常不是單一函式能不能呼叫，而是多個狀態同時更新時是否一致。因此我用 Hardhat 測試覆蓋供應、借款、利息、還款拆分、清算、reward、daily cap 與 LP share。README 中目前紀錄測試結果為 21 passing。

BankV3 End-to-End

驗證抵押、借款、利息累積、健康因子下降、清算、還款與提款限制。

LP Share Tracking

驗證多位 LP supply / redeem 後，aMDAI share 與 liquidityPool 份額是否正確。

Repayment Split

驗證 repay 時本金、LP yield 與 protocolTokenReserve 的拆分邏輯。

Liquidation

驗證 Health Factor 低於門檻後，清算額上限、抵押品轉移、LP 收益與 protocol share。

Reward Edge Cases

驗證 LP 與 borrower 的 BKT 累積、claim、withdraw 後 reward 變化，以及 dailyCap 限制。

DAO Parameter Change

驗證 Governor / Timelock 對協議參數的調整流程，確保治理函式不是任意帳戶可呼叫。
